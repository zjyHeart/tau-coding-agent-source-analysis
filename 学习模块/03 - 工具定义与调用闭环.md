# 03 - 工具定义与调用闭环

> [!summary] 本章解决什么
> 从单轮文字回答升级到“用户问题 → tool call → tool result → 模型回答”。这是学习 Agent 的第一个完整可运行闭环，先使用无副作用的模拟工具。

**官方概念参考**：[The agent loop](https://twotimespi.dev/concepts/#the-agent-loop) 与 [Tools](https://twotimespi.dev/concepts/#tools)。这页说明当前 Tau 的概念；本章具体代码行为仍以 `c66fb879` 源码和测试为准。

**本章定向阅读（同 commit 官方文档）**：[源文件](https://github.com/huggingface/tau/blob/c66fb879c1058f7b3d8514fb7f92c919d3c3e3b3/website/content/reference/tools.md) 的「工具参数与结果」。读完先回答：①工具名称从哪里来？ ②工具结果如何与 call ID 配对？

## 前置与产物

- 前置：[[02 - FakeProvider 与单轮回答]]。
- 练习脚本：本笔记目录下的 `tau-playground/toy_agent.py`；在 `tau-source/` 目录运行它。
- 源码：`src/tau_agent/tools.py` 的 `AgentTool`、`src/tau_agent/loop.py` 的 `_execute_tool_call()`。
- 产物：脚本输出、两次 provider 调用输入的对比表、完整事件序列。

## 步骤 1：读懂工具契约

`AgentTool` 包含名称、描述、参数 schema 和 `execute_fn`；`AgentToolResult` 装执行结果。读 `tests/test_agent_types.py::test_agent_tool_executes_with_pi_arguments`，写下工具函数四个入参的用途。`tool_call_id` 是关联键；`signal` 用于取消；`on_update` 用于进度，并非必定使用。

## 步骤 2：运行已有 toy agent

在 `tau-source` 目录执行：

~~~bash
rtk uv run python ../tau-playground/toy_agent.py
~~~

预期 `provider_calls: 2`；history 角色顺序为 `user → assistant → toolResult → assistant`。`read_demo` 只返回“模拟读取：README.md”，没有真正读磁盘。第一条 assistant 的可见文本为空，因为它只含 tool-call block。

## 步骤 3：给两次模型调用编号

把脚本里的两个 `FakeProvider` streams 标成调用①和②：①产出 `ToolCall`，loop 找到 `read_demo` 并执行；②拿到含工具结果的 history，再产出最终回答。对照 `tests/test_agent_loop.py::test_agent_loop_executes_tool_and_emits_tool_result_message_lifecycle` 的 `provider.calls[1][2]` 断言，说明第二次请求为何包含前三条消息。

## 步骤 4：逐事件核对

在输出中圈出两个 `turn_start`、一个 `tool_execution_start/end`、工具结果自己的 `message_start/end`。再运行：

~~~bash
rtk uv run pytest tests/test_agent_loop.py::test_agent_loop_executes_tool_and_emits_tool_result_message_lifecycle -q
~~~

写出“消息数 4，事件数更多”的原因，不必死背全部事件名；重点是消息历史与过程通知的职责不同。

## 步骤 5：自己替换一个参数

在练习脚本中将路径换成自己写的一个文件名，例如 `notes.txt`。预期 fake 工具只把新路径拼进返回字符串，两次 provider 调用数不变。不要在本章换成真正的 `read/write/bash`；副作用到 [[07 - Coding 工具与安全边界]] 再学。

## 完成检查

能指出 `ToolCall.name` 如何映射到注册工具、`ToolCall.id` 如何映射到结果、下一轮 provider 从哪里读到工具结果。若解释只能说“模型自己调用了工具”，回到步骤 3。

## 同步复刻任务（自己的学习版）

在 `mini_tau/tools.py` 定义工具名称、参数和异步执行函数；在 `mini_tau/agent.py` 写最小“收到 call → 查表执行 → 回填结果 → 再问 fake provider”。测试断言两次 provider 调用、四条消息及 call ID 一致。此时工具只返回固定字符串。

## 跟练卡：真正发生一次工具执行

**最小代码：**[toy_agent.py](../tau-playground/toy_agent.py) 是完整参考解；关键不是 `ToolCall` 的构造，而是把执行函数注册进 Harness：

```python
async def read_demo(tool_call_id, arguments, signal=None, on_update=None):
    return AgentToolResult(content=f"模拟读取：{arguments['path']}")

tool = AgentTool(name="read_demo", label="Read demo",
                 description="Return a fixed sample",
                 parameters={"type": "object"}, execute_fn=read_demo)
```

**运行：**在 `tau-source/` 执行 `rtk uv run python ../tau-playground/toy_agent.py`。**预期：**`provider_calls: 2`，history 角色为 `user → assistant → toolResult → assistant`，工具结果文字为 `模拟读取：README.md`。

**改一个变量：**把 call 中的路径换成 `notes.txt`，预测调用次数、消息数、工具结果文字。**参考解：**仍是 2 次 provider 调用和 4 条消息，只有结果变成 `模拟读取：notes.txt`。如果改了 `ToolCall.name` 却没有改 `AgentTool.name`，会走未知工具错误分支，留到模块 06 分析。

**排错：**`ToolCall` 只是模型请求；看到 `tool_execution_start/end` 和 `ToolResultMessage` 才能证明本机执行函数被调用。脚本返回固定字符串，不会实际读取 `README.md`。
