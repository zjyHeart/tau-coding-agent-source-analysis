# 09 - 提示词上下文与项目信任

> [!summary] 本章解决什么
> 把模型看到的 system prompt、项目指令、skills 和实际可执行工具拆开。项目资源能影响模型行为，project trust 管理资源是否加载；它们都不是文件/进程权限隔离。

**官方概念参考**：[Project instructions](https://twotimespi.dev/concepts/#project-instructions-agentsmd) 与 [Skills and prompt templates](https://twotimespi.dev/concepts/#skills-and-prompt-templates)。这页说明当前 Tau 的概念；本章具体代码行为仍以 `c66fb879` 源码和测试为准。

**本章定向阅读（同 commit 官方文档）**：[源文件](https://github.com/huggingface/tau/blob/c66fb879c1058f7b3d8514fb7f92c919d3c3e3b3/website/content/guides/skills-and-prompts.md) 的「Skills / Prompt templates」。读完先回答：①skill 描述何时进入 prompt？ ②模板与可执行工具有什么区别？

## 前置与产物

- 前置：[[08 - Provider 适配与自定义 API]]；理解 system/messages/tools 会作为 provider 请求输入。
- 源码：`src/tau_coding/system_prompt.py`、`context.py`、`resources.py`、`skills.py`、`prompt_templates.py`、`project_trust.py`。
- 产物：一张“发现资源 → trust 决策 → 加载 → 构造 prompt → provider”流程表。

## 步骤 1：先看默认 prompt 的组成

从 `build_system_prompt()` 入手，记录默认说明、cwd、日期、工具说明、guidelines、项目上下文、skills 分别从哪里来。用 `tests/test_system_prompt.py::test_default_prompt_includes_tools_guidelines_date_and_cwd` 核对。注意“在 prompt 中描述工具”和“真正注册到 Harness 的工具”是两个动作。

## 步骤 2：看资源发现与优先级

读 `context.py::discover_project_context_with_diagnostics()` 和 `resources.py::discover_system_prompt_resources()`。对照 `tests/test_context.py::test_discovers_user_project_and_agents_context_files`、`tests/test_resources.py::test_system_prompt_files_replace_by_precedence_and_append_in_order`，画出用户级、项目级、显式配置的来源。不要凭文件名猜“自动全部注入”。

## 步骤 3：单独理解 project trust

读 `project_trust.py` 的 protected resource 检测/决策入口。运行 `tests/test_project_trust.py::test_untrusted_resource_plan_keeps_user_resources_only` 与 `test_project_extensions_need_trust_and_additional_opt_in`。记录“不信任时哪些资源不加载”和“额外允许扩展”不是同一个开关。信任决策不能限制 Bash 或 Python 扩展在操作系统层的能力。

## 步骤 4：在练习目录做一个无风险对照

在 `tau-playground` 的临时子目录放一份只含普通文字的 `AGENTS.md`；参照上述测试，比较“资源被发现”和“内容最终进入 prompt”这两个阶段。实验只读取你自己创建的文本，不使用扩展或真实 API。输出两列：资源路径、是否进入最终 prompt，并注明对应的 trust 条件。

## 选做：真实产品里调用 skill、模板和 thinking mode

完成模块 08 的真实模型连接后，在自己信任的 `tau-playground/` 项目内创建 `.tau/skills/tau-note/SKILL.md`：

```md
---
description: 用三点总结一段文字。
---
只根据用户给的文字列出三点，不读取其他文件。
```

再创建 `.tau/prompts/three-points.md`，内容为 `请用三点总结：$ARGUMENTS`。从该项目启动 Tau，先运行 `/skills` 确认 skill 出现在列表，再输入 `/skill:tau-note 总结这段测试文字`；接着运行 `/prompts` 并输入 `/three-points 这段测试文字`。比较两次 prompt 展开方式；不要把这两个文件放到全局用户目录。

再用 `/think` 或 `Shift+Tab` 切换模型支持的 thinking level，用 `Ctrl+T` 控制 reasoning 的**显示**。记录模型、可选档位及一次请求的变化；显示开关和请求档位不是同一个设置。若自定义 provider 未声明 `thinking_levels` 或模型不支持，先记录“不可用”，不要强行推断中转端支持。依据：[同 commit Skills & prompts](https://github.com/huggingface/tau/blob/c66fb879c1058f7b3d8514fb7f92c919d3c3e3b3/website/content/guides/skills-and-prompts.md)、[Thinking modes](https://github.com/huggingface/tau/blob/c66fb879c1058f7b3d8514fb7f92c919d3c3e3b3/website/content/guides/context.md)。

## 运行验证与完成检查

~~~bash
rtk uv run pytest tests/test_system_prompt.py tests/test_context.py tests/test_resources.py tests/test_project_trust.py -q
~~~

能区分模型指令、工具注册、项目资源发现、trust 决策、沙箱五个概念；能解释为什么看到 `AGENTS.md` 不等于允许执行其中任何命令。

## 同步复刻任务（自己的学习版）

写一个纯函数 `mini_tau/prompt.py`，把固定说明、工具说明和一份你自己创建的项目指令拼接；测试验证顺序与去重。把“是否允许加载项目文件”作为显式输入，不把 prompt 文本误当权限边界。
